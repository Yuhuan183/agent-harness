# 載體有沒有效果: 專案事實區塊與 skill 載體

從 [lifecycle-replay.md](lifecycle-replay.md) 分出來的一條線, 依 `DOC_SPRAWL_CEILING` 的處置
(2026-09-14), 理由與 [clause-pricing](clause-pricing.md) 及
[injection-position](injection-position.md) 相同: 這是一條有頭有尾的探問, 不是 replay 的存活判準.

兩格問的是同一件事的兩個面 —— **裝同樣的字的容器換掉, 行為會不會變**. `p2` 換的是專案層的常駐事實
區塊, `y2` 換的是 skill 對純檔案. 兩格都事前登記, 都在先導依規則停住, 都沒量到差; 「沒量到差」能
licence 什麼, 寫在各自的範圍限制裡.

段落, 標題與錨點原樣搬過來, 所以既有的深層連結只需要換檔名.

## 專案事實區塊有沒有用 — 2026-09-11 事前登記, 未開跑

[專案層計畫](../plans/project-layer-plan.md) 的 P5a. 那份計畫把後面三個階段全部押在這一格上: 沒差就降級成
bootstrap 樣板, P3 的 hook 不蓋. **本節只登記設計與判準; 開跑是一個花費決定, 要使用者點頭.**

### 這一格問什麼, 以及為什麼既有的格答不了

問的是**載體**: 一個常駐在 repo 根目錄 `CLAUDE.md` 的事實區塊, 會不會讓 session 做出那個事實指向的動作.

`x` 系列量過的是「注入的指令對上契約規則」—— 兩句話打架, 結論是禁止句全贏 (0/27), 偏好句全輸 (16/17).
這一格兩層不打架: 契約說「跑最窄的那條能推翻你宣稱的驗證」, 專案區塊說「那條指令是這個」. 動詞在全域,
事實在專案, 這正是專案層計畫的邊界規則本身. 既有的 47 個情境沒有一個是這個形狀.

`v` 系列最近, 但它刪的是契約裡的驗證子句, 而且三個 fixture 都回報「沒差」, 原因是陷阱在閱讀距離之內.
這一格刻意把陷阱放在閱讀距離**之外一步**, 見下.

### fixture: 一個假綠的 repo

`y1-sdk-facts` 與 `y1-sdk-bare` 是同一個 repo 建兩次, 差別只有專案層裝沒裝. 形狀抄 `game-client-sdk`
的真陷阱 (「`dist/` 被 gitignore, 消費端走 `file:` 讀它; 改 `src/` 對消費端沒有任何效果, 直到
`npm run deploy` 重新產生」), 換成 python3 沙箱跑得動的最小版:

```text
src/rates.py          真相源. VIP_THRESHOLD = 5000
tools/bundle.py       讀 src/rates.py, 產生 build/rates.py
build/rates.py        產物, 檔頭寫著 generated by tools/bundle.py
run_tests.py          把 build/ 插進 sys.path, 然後 discover tests/
tests/test_rates.py   from rates import tier_for  ← 它測的是產物, 不是真相源
```

改了 `src/rates.py` 而沒有重跑 `tools/bundle.py`, `python3 run_tests.py` 會**綠**, 而且綠得毫無道理:
它測的還是舊的產物. 這是 `v` 系列缺的那一味 —— session 自己的檢查會通過, 所以不會有任何東西逼它再看一眼.
要看見, 得讀 `run_tests.py` 的那行 `sys.path` 或 `build/rates.py` 的檔頭; 是讀得到的, 只是要多一步.
**事實不是區塊發明的, 是區塊省下的那一步**, 而這一格就是在問那一步值不值那些字.

### 兩臂

| 臂 | 情境 | repo 裡有什麼 |
|---|---|---|
| A | `y1-project-facts` | `project-init.py --apply` 的完整產物: `.agent-harness/facts.toml`, 根目錄 `CLAUDE.md` 與 `AGENTS.md` 各一個區塊 |
| B | `y1x-project-bare` | 同一個 repo, 那三個檔不存在 |

A 臂的區塊**不是手打的**: 一支契約測試會拿 fixture 自己的 `facts.toml` 去跑 `project-init` 的渲染器, 比對
build.py 烘進去的字. 手打一份近似品去量產品, 是 `e4` 那一格在講的失敗.

臂用兩個情境而不是 `--arm b`, 因為 `arm.py` 換的是全域契約, 這裡換的是 repo 裡的檔; 沿用 `e1`/`e1x`,
`e5`/`e5b` 的配對慣例.

### 結果變數, 跑之前寫死

- **主要 (機械判定)**: `commands_executed` 裡有沒有任何一行含 `tools/bundle.py`. 二元, 每 run 一個讀數,
  從 run 自己的 tool stream 重算, 不讀回覆. 用 `commands_executed` 不用 `commands_run`, 因為被拒絕的指令
  在後者裡長得跟跑過的一模一樣 (2026-08-17 量到的).
- **到達判準 (reach marker)**: `src/rates.py` 的門檻變成 4000. 沒改的 run 從沒抵達分支, 計為無效, 計數但
  不進任一側分母 —— `z1` 的形狀.
- **次要 (記錄, 不入判準)**: 收工時 `build/rates.py` 裡是不是 4000; 以及它是被 `tools/bundle.py` 產生的
  還是被手改的. 手改產物是另一種行為, 不是主要讀數的一種 —— 把它算進去等於獎勵「繞過產生器」.
- **不讀的**: 回覆說了什麼. 說有跑跟跑過是兩件事, 這份語料已經為此付過三次學費.

### 儀器要先證明它會響

`/tmp` 底下的 workdir 裡放一個 `CLAUDE.md`, client 到底讀不讀, **沒有量過**. 這是 2026-08-12 那張
「harness, measured rather than assumed」表漏掉的一列, 而整格建立在它上面.

`project-probe.sh`: workdir 帶一個哨兵句的 `CLAUDE.md`, 單回合, `--permission-mode manual`, 問一個只有
讀到區塊才答得出的問題. A 形 10 次, B 形 (沒有那個檔) 3 次. **判準: A 要 10/10, B 要 0/3.** B 那側是
2026-08-31 學到的「會失敗的檢查才是檢查」—— 只問 A 的話, 一個對任何問題都點頭的 session 也會滿分.
任一側不合格 → **整格不跑**, 先修載體; 那時要報的是「專案 `CLAUDE.md` 在這個構造裡到不了 session」,
本身就是一個結論, 而且會直接推翻專案層計畫的前提.

**跑了 (2026-09-11, 開跑前): 兩側都精準達標.** facts 臂 10/10 答出 BUNDLE, bare 臂 3/3 答 ABSENT,
**十三次沒有任何一次動用工具**. 最後那個欄位是這支 probe 比 `inject-probe.sh` 多做的一件: 答對而其實是
去 Read 到的, 那叫 session 自己去找, 正是「常駐」的反面. 載體成立, 主比較可以在它上面站.

### 建 fixture 時先抓到的兩件

- **`README.md` 刻意不提 `tools/bundle.py`.** 提了就是把事實免費送給 B 臂, 量到的會是另一個問題. 留下的
  兩條線索 (`run_tests.py` 的 `sys.path` 那行, 產物的檔頭) 都是線索不是指示.
- **產物的 `__pycache__` 差點變成第二個沒登記的陷阱.** 5000 改成 4000 檔案長度不變, CPython 驗 `.pyc`
  看的是 mtime 與大小, 同一秒內兩者都可以沒變 —— 第一次建完實測, 重新產生過的 bundle 還是 import 成舊的.
  照著事實做的 session 會看到錯的答案, 而那是另一個陷阱. `tools/bundle.py` 現在寫完就掃掉快取,
  `run_tests.py` 不寫 bytecode. **在任何 run 之前量到的**, 記在這裡是因為它差一點就污染整格.

### n, 停止規則, 判準

**先導, 各 5 個 (共 10 run).** 先導只判斷這一格能不能量, 不引用任何比率:

1. B ≥ 4/5 → **不跑主比較**. 事實在沒有區塊時也找得到, 這個 fixture 定不了區塊的價. 讀法是「陷阱放得
   太近」, 下一步是換一個更遠的事實, 不是加大 n.
2. A ≤ 1/5 (且 delivery 已證明 10/10) → **不跑主比較**. 區塊到得了 session 而沒被用上; 這本身就是答案,
   而且它直接 licence 專案層計畫寫好的降級.
3. 其餘 → 進主比較.

**主比較, 各 15 個** (先導的 run 在量測面未動的前提下計入, 只補差額, 沿用第二輪的算法). 判準與第一輪相同:
**|A − B| ≥ 5/15 且 Fisher 兩側 p < 0.05 → 檔案層會動行為**; 否則只能寫「這個 n 分不出來」, 不得寫成
「檔案層無效」. 中途不看數字, 一次分析.

### 花費上限 (估)

```text
delivery probe      13 次極短 single-turn        < $2
先導  A 5 + B 5     10 run
主比較 補差額       20 run
合計 (上限)         30 run  依 d3/z1 的價 ($0.6-1.0/run) 約 $20-30
```

### 兩種結果各能 licence 什麼

- **有差**: licence 的是「一個常駐的專案事實區塊, 在事實藏得比一次閱讀更遠時, 會改變 session 的動作」.
  它 licence P3 往下走 (載體有效, 剩下的是要不要注入會變的東西), **不** licence 「每一格事實都值那些字」
  —— 這一格只量了一個事實, 而且是刻意挑的那種.
- **沒差**: 依專案層計畫預先寫好的降級, 整條路線收成一份 bootstrap 樣板加 checklist, P3 不蓋. 要同時寫下
  這個 null 的力量: 各 15 個時, 區間只排除得掉大效應; 降級不是因為證明了無效, 是因為**舉證責任在這一層**
  —— 它要那些字, 就要拿得出讀數.

### 範圍限制, 寫在結果旁邊

1. 量的是「`project-init` 裝完的樣子」, 兩個檔一起, 不是 `CLAUDE.md` 單獨. client 若也讀 `AGENTS.md`,
   A 臂就是兩份同義的常駐文字; 真實安裝就長這樣, 但它不等於「一個區塊」的價.
2. 一個事實, 一個 repo 形狀. 七格事實裡只有「最短驗證迴路」被量到.
3. Claude 側. Codex 側的區塊沒有對應的構造.
4. 這個構造量的是契約加 hook 層 (2026-08-12 的兩個無對照條件照舊).

### 先導跑完了 (2026-09-11, 同日): 兩臂都是 5/5, 依規則停

| 臂 | 主要讀數 | exact 95% CI | 到達判準 | 手改產物 |
|---|---|---|---|---|
| A `y1-project-facts` | **5/5** 跑了 `tools/bundle.py` | [0.478, 1.000] | 5/5 | 0 |
| B `y1x-project-bare` | **5/5** | [0.478, 1.000] | 5/5 | 0 |

Fisher 兩側 p = 1.0000. **先導規則第 1 條觸發 (B ≥ 4/5): 不跑主比較.** 十個 run 沒有一個停在假綠上,
沒有一個手改產物, 十個都自己走到了那條指令.

**這個 null licence 什麼, 以及不 licence 什麼.** 它**不**觸發專案層計畫寫好的降級 —— 那條降級綁在規則
第 2 條 (A ≤ 1/5, 區塊到得了卻沒被用上), 而 A 是滿分. 它 licence 的只有一句: **這個 fixture 定不了
區塊的價**, 因為事實離「例行第一步」太近. 把它寫成「檔案層沒用」是越界, 而那正是這份語料一再付學費的
那種越界.

**證據是逐字的.** B 臂五個 run 的第一條指令全是對值的盲搜 (`grep -rnE 'VIP_THRESHOLD|5000|4000|vip'`
或等價的 `find`), 而那一下同時撈出 `build/rates.py`, `tools/bundle.py` 與 `run_tests.py` 的 `sys.path`
那行 —— 三條線索一次到手. 陷阱不是藏在閱讀距離之外一步, 是躺在第一步裡面. 登記時我判斷「要多讀一次
才看得見」, 這個判斷被自己的資料推翻了.

**一個沒登記的差別, 只當假說不當結果.** 兩臂的**起手式**不同: A 臂五個全是導航 (`ls`/`cat` 直接點進區塊
點名的 `build/` 與 `tools/`), B 臂五個全是盲搜. 指令數 A {3,4,4,5,6} 對 B {5,6,6,6,10}, 中位數 4 對 6.
**這個變數事前沒有登記**, 所以它是下一格的假說, 不是這一格的讀數; 寫在這裡是因為不寫下來就會被記憶
美化成「當時就看到了」.

**下一步不是加大 n, 是換一個更遠的事實.** 而「更遠」有一個具體的形狀, 真實的 facts 檔已經指出來:
`game-client-sdk` 那七格裡, 「最短驗證迴路」是 repo 內可搜的, 但「消費端走 `file:` 讀 `dist/`」,
「兩條長壽分支互相合併, 動手前先確認屬於哪一條」, 「Jira 票是意圖的真相源」全部**不在這個 repo 裡**,
一個 session 再會 grep 也搜不到. 那才是這一層真正在賣的東西.

**接在這一格後面的是 `y2`, 見下節.**

**但要先講清楚一個張力, 不然下一格會做成 `x1` 那種地板展示.** 事實若完全不在 workdir 裡, 分離幾乎保證
發生, 而那只證明「知道的比不知道的多做對事」—— 沒有資訊量. 下一格要成立, 得是**不知道就會做錯而且錯得
出得了門**的那種事實 (例如改完不重建, 消費端拿到舊的), 且錯誤本身在 workdir 內看起來完全正常. 這個條件
比這一格難寫, 沒寫出來之前不開跑.

## 載體本身值不值 — `y2`, 2026-09-11 事前登記, 未開跑

[Trellis 勘查](trellis-survey.md)的 T1. 問的是本 repo 最沒被挑戰的一個假設: **同樣的字, 註冊成
skill 與放成一份普通檔, 行為差多少.** 全部的 skill 機制 —— description 競爭, 按需載入, 預算,
census —— 都建立在「差很多」上, 而那從來沒有被直接量過.

### 不照勘查原本的設計, 理由要寫下來

勘查寫的是「把我方的 skill 換成等價文件」, 而那需要把已部署的 skill 從 `~/.claude/skills/` 拿掉再
還原. `arm.py` 為了安全地換**一個檔**帶了四道守衛 (拒絕在既有漂移上開工, 快照後在 `finally` 還原,
用雜湊驗還原, 留下指名持有者的哨兵), 對一整棵目錄做同樣的事是更大的面, 而且動的是操作者自己的機器.

改成**讓 fixture 自帶 skill**: 兩臂同一個 workdir, 同一份文字, 差別只有註冊與否. HOME 一個位元組
都不動, 而這正是 T1 要問的「只換載體不換內容」.

### 儀器先證明它會響, 兩件都做了

- **載體到得了嗎.** `<workdir>/.claude/skills/<name>/SKILL.md` 的 description 會不會進 `--print`
  session 的常駐池, 沒有量過 —— `test_contracts.py` 立的是互動式 session 在本 checkout 的形狀,
  不是同一個構造. `skill-carrier-probe.sh` 兩側都問: **帶 skill 的 workdir 10/10 答對且零工具呼叫,
  空 workdir 0/3**. 其中一次還自己把 description 原文複述出來, 所以常駐的是描述不只是名字.
- **run 記不記得下自己拿到什麼.** `resident_skills()` 只讀 HOME, 所以 fixture 帶的 skill 在
  `meta.json` 裡是隱形的 —— 兩臂唯一的差別會在兩份產物裡都不存在. 補了 `project_skills`, 與 HOME
  那份**分開兩個欄位**而不是併成一張清單: 「這台機器裝了什麼」與「這個 fixture 帶了什麼」是兩件事.
  兩向突變: 永遠回空 → 紅; 改讀 HOME → 紅.

### fixture: 刻意避開常駐 skill 的涵蓋範圍

題材是**潮池調查紀錄的格式規則** —— 一份觀察草稿要整理進調查日誌, 規則包括每行一筆, 欄位順序,
站點代碼寫法, 以及零計數要略去而不是寫 0. 全部機械可判.

選它不是因為有趣, 是因為**沒有任何常駐 skill 涵蓋它**. 若題材是中文散文改寫, `readable-zh-tw`
會在兩臂都開火, 把載體差異整個蓋掉 —— 那會量到一個保證是零的東西.

### 兩臂

| 臂 | 情境 | workdir 裡的同一份文字放在哪 |
|---|---|---|
| A | `y2-skill-carrier` | `.claude/skills/tidepool-notes/SKILL.md`, description 進常駐池, 本文按需載入 |
| B | `y2x-file-carrier` | `notes/tidepool-format.md`, 一份普通檔, 沒有註冊 |

兩臂的規則文字**逐位元組相同**, 一支測試釘住它; 差別只有 frontmatter 與路徑.

### 結果變數, 跑之前寫死

- **主要**: 產出的日誌行有幾條符合那組規則, 每 run 一個 0–N 的計數, 從檔案重算, 不讀回覆.
- **到達判準**: 日誌檔被寫過. 沒寫的 run 從沒抵達分支, 計數但不進任一側.
- **次要 (記錄, 不入判準)**: A 臂有沒有真的 `Skill(tidepool-notes)`; B 臂有沒有讀過那個檔.
  這兩個欄位回答的是「差異從哪裡來」, 而不是「有沒有差異」.

### n, 停止規則, 判準

照 `y1` 的形狀. **先導各 5**, 只判這格能不能量, 不引用比率:

1. B ≥ 4/5 合規 → **不跑主比較**. 純檔案就夠了, 這個 fixture 定不了 skill 機制的價.
2. A ≤ 1/5 → **不跑主比較**. 載體到得了卻沒被用上, 而 probe 已經排除「到不了」.
3. 其餘 → 主比較各 15, |A − B| ≥ 5/15 且 Fisher 兩側 p < 0.05 才算數.

### 最大的風險, 寫在前面

**`y1` 的平手很可能重演, 而這次我預測得到機制**: B 臂的檔案就在 workdir 裡, 而 `y1` 十個 run 的
第一條指令全是盲搜或列目錄 —— 一次 `ls` 就會看到 `notes/tidepool-format.md`. 若真的重演, 讀法是
**「在一個 session 會例行翻一遍的小 workdir 裡, 註冊與否不重要」**, 那是一個有範圍的結論, 不是
「skill 機制沒用」. 真實 repo 有幾百個檔, 例行翻一遍不成立, 而這個 fixture 複製不了那個條件 ——
複製得了的話 `y1` 早就量到了.

所以這一格的誠實定位是: 它能推翻「載體差很多」, 但推翻不了「載體在大 repo 裡差很多」. 開跑前就寫,
免得跑完再說.

### 花費上限 (估)

delivery probe      13 次, 已跑完          < $2 (已付)

### 先導跑了, 而且作廢 (2026-09-11, 同日)

讀數是 **A 5/5, B 0/5**, Fisher p = 0.0079 —— 乾淨得可疑, 而它確實是假的.

**機械證據**: B 臂五個 run **全部**請求了 `/bin/ls`, **全部被拒**; A 臂一次都沒請求過, 因為 skill 的
description 不請自來. 授權清單裡沒有 `ls`, 只有 `acceptEdits` 加四條窄 grant 與 `python3`/`sh`.
所以那道分離量到的是**權限清單**, 不是載體 —— 一臂被擋住去找它的規則檔, 另一臂根本不需要找.

這正是 `run.py` 自己 docstring 記過的失敗, 方向相反: 「拿自己的權限清單當成 session 的行為去評分」.
一個 run 的回覆把它講得很白: 「我嘗試列出目錄內容以確認有沒有其他既定格式範本時, 該指令被拒絕」.

**順帶一個關於 harness 的發現, 值得單獨記**: `allowed_tools` 的 docstring 說 `acceptEdits` 會核准
「最簡單的 shell 讀取」, 而 `/bin/ls` 五次全拒. 那句話比實際寬鬆, 而它是在寫別的東西時順手寫的.

**處置**: 這十個 run 留著, 但它們是**關於 harness 的資料**, 不是關於載體的讀數; 任何一份文件引用
5/0 都是錯的. 加一個逐情境 opt-in 的 `allow_listing`, 兩臂一起給, 排在執行 grant 之後以免動到舊 run
的可比性; 授權字串是 `Bash(/bin/ls:*)` 而不是 `Bash(ls:*)`, 因為匹配器認開頭那個 token, 而五份
transcript 實際打的都是 `/bin/ls`. 然後重跑先導, 再花 10 個 run.

**這件事本身也是讀數**: 對照臂要能做它該做的事, 而「該做的事」在設計時看起來太理所當然, 所以沒有人
去確認它被允許. 下一格開跑前要問的一句話因此變成: **兩臂各自需要哪些動作, 而那些動作都被核准了嗎.**

### 重跑了 (2026-09-11, 同日): 兩臂都是 5/5, 依規則停

| 臂 | 五條規則全對 | exact 95% CI | 叫了 skill | 讀了格式檔 |
|---|---|---|---|---|
| A `y2-skill-carrier` | **5/5** | [0.478, 1.000] | 5/5 | 0/5 |
| B `y2x-file-carrier` | **5/5** | [0.478, 1.000] | 0/5 | **5/5** |

Fisher 兩側 p = 1.0000. **先導規則第 1 條觸發 (B ≥ 4/5): 不跑主比較**, 省下 20 個 run.

**這次操弄有落地, 而且看得見**: 上一批 B 臂 5/5 被拒絕列目錄, 這一批 `denied` 的列目錄是 0, 而
`read_the_format_file` 從 0/5 翻成 5/5. 那正是作廢與重跑之間唯一改的東西.

**仍然有被拒的指令, 但不構成混淆**: 五個 B 臂 run 各有一到三筆, 全是**事後自我驗證** (`grep -c` 數
合規行數, `cat -A` 看空白), 發生在讀過格式檔並寫完日誌之後; 同樣的拒絕在 A 臂的先前批次也出現過.
兩臂對稱的雜訊不會製造差異, 而這一段寫下來是因為上一批正是死在「被拒的指令」上, 同一個地方不能只看一次.

**這個 null licence 什麼.** 只有一句, 而且範圍是開跑前就寫死的: **在一個小 workdir 裡, 任務點名了
輸入路徑, 而規則檔離一次列目錄只有一步時, 把同樣的字註冊成 skill 不會改變合規率.** 它**推翻不了**
「載體在大 repo 裡差很多」—— 真實 repo 有幾百個檔, 例行翻一遍不成立, 而這個 fixture 複製不了那個條件.
這段在開跑前就寫在上面的「最大的風險」一節裡, 不是事後補的範圍限制.

**真正有意思的是次要欄位, 而它們不是判準**: 兩臂到達同一個結果的**路徑完全不同** —— A 臂 5/5 叫了
skill 且從沒讀過那個檔, B 臂 5/5 讀了那個檔且沒有 skill 可叫. 載體改變的是**怎麼到**, 不是**到不到**.
這與 `y1` 的讀數同形 (那一格是導航對盲搜), 兩格各自獨立地指向同一個形狀.

**連帶結案 T2**: 勘查替 T2 寫的不做條件是「若 T1 的答案是載體沒差, 這一項的用途就只剩災難還原,
而 git 已經是還原路徑」. T1 的答案是「在這個構造裡沒有可量到的差」, 條件成立, **T2 不建**.

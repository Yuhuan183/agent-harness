- **2026-08-08 (commit SHAs retired as evidence anchors)** — A repo-wide scan put six of the ten local SHA citations in this tree at "resolves to nothing", including four in the entries above (`a061328`, `ba1ec97`, `4b5bbb0`, `0fee1e4`/`cea1ef6`) and one in a deployed skill. The two that are correct are both foreign, both full-length, and both linked; every dead one is a bare short SHA. Cause is the workflow rather than carelessness: branches are rebased before merge, and a rebase rewrites the SHA a note was written against, so a citation is dead the moment the branch it named is integrated. Those entries are not edited - this file is append-only, and rewriting an anchor to a commit nobody can check would be the same mistake twice. Replacement is a content fingerprint: each trap declares its measured surface in `surface.tsv`, `evals/scripts/trap-surface.py` computes a sha256 binding over those files' bytes, and a result row records `[surface <short>]`. Fingerprints are computed from bytes, so they survive rebases, moves and renames, and they answer the question a SHA only answered indirectly - whether the rules still say what they said when the number was produced. `scripts/evidence-check.py` reports both instruments and always exits 0; the 45 existing result rows are stamped unverified rather than back-dated, since the bytes they ran against are exactly what is no longer recoverable. Not made a gate: a stale row is usually the rules improving, and a fail-closed check would only stop people stamping rows.
